Problemas Críticos
1. SQL Injection via GET_LOCK com data não sanitizada
Gravidade: Crítica
Arquivos: app/reservas/create.php, app/reservas/edit.php

Problema:


$lock_name = 'reserva_' . (int)$ambiente . '_' . $data;
$locked = $conn->query("SELECT GET_LOCK('{$lock_name}', 5)")->fetch_row()[0];
$data vem de parse_data() sem sanitização antes da interpolação direta na query SQL.

Impacto: Atacante pode injetar SQL via campo de data.

Como reproduzir: Enviar data_reserva com caracteres SQL: 10/01/2024', 5); DROP TABLE reservas; --

Correção:


$stmtLock = $conn->prepare("SELECT GET_LOCK(?, 5)");
$stmtLock->bind_param("s", $lock_name);
$stmtLock->execute();
2. Sem rate limiting no login — força bruta irrestrita
Gravidade: Crítica
Arquivo: Endpoint de autenticação

Problema: Nenhum limite de tentativas de login. Um atacante pode fazer brute force infinito.

Impacto: Comprometimento de qualquer conta com senha fraca.

Como reproduzir: Enviar 10.000 requisições POST com senhas diferentes — nenhuma bloqueada.

Correção: Implementar bloqueio por IP após 5 tentativas falhas (APCu, Redis ou tabela de tentativas no banco).

3. Permissões não revalidadas contra o banco de dados
Gravidade: Crítica
Arquivo: app/bloqueios/criar_ajax.php

Problema:


if ($_SESSION['usuario_tipo'] !== 'admin') {
    http_response_code(403);
    exit;
}
Confia cegamente no valor da sessão. Se a sessão for sequestrada ou manipulada, o atacante passa pela verificação.

Impacto: Escalação de privilégios via session hijacking.

Correção: Revalidar o papel do usuário contra o banco a cada operação sensível.

4. Path Traversal / LFI em relatórios
Gravidade: Crítica
Arquivo: app/relatorios/gerar.php

Problema:


include __DIR__ . "/reports/{$tipo}.php";
Mesmo com in_array() strict, $tipo vem do GET sem sanitização adicional. Uma falha no whitelist expõe LFI completo.

Impacto: Leitura de arquivos arbitrários do servidor.

Como reproduzir: gerar.php?tipo=../../../config/db

Correção:


$tipo = preg_replace('/[^a-z_]/', '', $_GET['tipo'] ?? '');
if (!in_array($tipo, $relatorios_validos, true)) {
    die('Relatório inválido.');
}
5. XSS via nome de ambiente em resultado de busca
Gravidade: Crítica
Arquivo: app/reservas/index.php

Problema:


const html = data.map(r => `
    ...${r.nome_ambiente}...
`).join('');
r.nome_ambiente é interpolado diretamente no HTML sem escaping.

Impacto: Admin cria ambiente com nome <script>alert('xss')</script>, qualquer usuário que pesquisar executa o script.

Como reproduzir: Criar ambiente com nome contendo HTML/JS malicioso e pesquisar reservas.

Correção: Usar element.textContent em vez de template literals com HTML.

6. Race condition com datas invertidas silenciosamente
Gravidade: Alta
Arquivo: app/bloqueios/criar_ajax.php

Problema:


if ($data_fim < $data_inicio) {
    [$data_inicio, $data_fim] = [$data_fim, $data_inicio]; // silencioso!
}
Em vez de retornar erro, inverte as datas sem avisar o usuário.

Impacto: Admin pensa que bloqueou Jan→Dez, sistema cria Dez→Jan (invertido).

Correção: Retornar erro claro: "A data de fim não pode ser anterior à data de início."

7. Locks MySQL sem try/finally — resource leak garantido
Gravidade: Alta
Arquivos: app/ambientes/create.php, app/reservas/create.php, app/bloqueios/criar_ajax.php

Problema:


$locked = $conn->query("SELECT GET_LOCK('ambientes_write', 5)")->fetch_row()[0];
// ... código que pode lançar exceção ...
$conn->query("SELECT RELEASE_LOCK('ambientes_write')"); // nunca executado se ocorrer erro
Impacto: Lock prende por 5s. Em produção com erros frequentes, o sistema trava.

Correção: Envolver em try/finally para garantir liberação do lock.

8. Checkbox "ativo" com lógica quebrada nas edições
Gravidade: Alta
Arquivos: app/ambientes/edit.php, app/funcionarios/edit.php, app/bloqueios/edit.php

Problema:


<?= (isset($_POST['ativo']) && $_SERVER['REQUEST_METHOD'] === 'POST' ? true : (bool)$ambiente['ativo']) ? 'checked' : '' ?>
isset($_POST['ativo']) && POST ? true : ... — se o POST chegou com ativo ausente (checkbox desmarcado), a condição POST === true retorna true por outro caminho.

Impacto: Impossível desativar um ambiente/funcionário pela interface.

Como reproduzir: Abrir edição de ambiente ativo → desmarcar checkbox → salvar → continua ativo.

Correção:


<?= ($_SERVER['REQUEST_METHOD'] === 'POST' ? isset($_POST['ativo']) : (bool)$ambiente['ativo']) ? 'checked' : '' ?>
9. Senha mínima de 4 caracteres
Gravidade: Alta
Arquivos: app/usuarios/create.php, app/usuarios/edit.php

Problema:


if (strlen($senha_raw) < 4) {
    $erro = "A senha deve ter no mínimo 4 caracteres.";
}
Impacto: Senha "aaaa" é válida. Brute force trivial.

Correção: Mínimo 12 caracteres com complexidade, ou pelo menos 8 com aviso.

10. Upload de fotos sem validação de tipo MIME server-side
Gravidade: Alta
Arquivo: app/reservas/edit.php

Problema: O upload vai direto ao Cloudinary usando o arquivo temporário sem verificar o tipo real do arquivo (apenas o accept do HTML, que é facilmente burlado).

Impacto: Upload de arquivo PHP disfarçado de .jpg.

Correção:


$finfo = new finfo(FILEINFO_MIME_TYPE);
$mime = $finfo->file($fotos['tmp_name'][$id_item]);
if (!in_array($mime, ['image/jpeg', 'image/png', 'image/webp'])) {
    $erro = "Tipo de arquivo inválido.";
    continue;
}
11. Transação de vistoria com upload Cloudinary dentro do rollback
Gravidade: Alta
Arquivo: app/reservas/edit.php

Problema: O upload para o Cloudinary ocorre dentro da transação do banco. Se o Cloudinary falhar, o rollback desfaz os dados do banco, mas a foto já pode ter sido enviada. Se o banco falhar depois do upload, a foto fica no Cloudinary sem registro.

Impacto: Estado inconsistente — fotos sem vistoria ou vistorias sem foto.

Correção: Fazer todos os uploads antes de abrir a transação.

12. Exposição de erro de conexão ao banco
Gravidade: Alta
Arquivo: config/init.php

Problema:


die("Falha na conexão: " . $conn->connect_error);
Impacto: Mensagem de erro técnica exposta ao usuário (host, usuário, detalhes do MySQL).

Correção:


error_log("DB Connection Error: " . $conn->connect_error);
die("Erro ao conectar ao sistema. Contate o administrador.");
13. CSP com unsafe-inline — proteção XSS nula
Gravidade: Alta
Arquivo: config/init.php

Problema:


header("Content-Security-Policy: ... script-src 'self' 'unsafe-inline' ...");
unsafe-inline permite qualquer <script> inline, anulando completamente a CSP como defesa XSS.

Correção: Usar nonce para scripts inline específicos e remover unsafe-inline.

14. Dados pessoais (telefone) registrados em logs de auditoria
Gravidade: Alta
Arquivo: app/funcionarios/index.php

Problema:


$detalhes = "nome: {$row['nome_completo']} | telefone: {$row['telefone']}";
registrar_log($conn, ..., $detalhes);
Impacto: Violação de LGPD/privacidade — dados pessoais desnecessários em logs.

Correção: Registrar apenas identificadores, não dados pessoais.

Problemas Médios (seleção)
15. Validação de formato de hora ausente
Gravidade: Média
Arquivo: app/reservas/create.php

Problema: hora_inicio e hora_fim aceitam qualquer string. 25:70 passa pela validação.

Correção:


if (!preg_match('/^\d{2}:\d{2}$/', $hora) || (int)explode(':', $hora)[0] >= 24) {
    $erro = "Hora inválida.";
}
16. Valores monetários negativos aceitos
Gravidade: Média
Arquivo: app/reservas/create.php

Problema: floatval($_POST['valor_cobrado']) aceita -1000.

Impacto: Reservas com valor negativo no sistema financeiro.

17. Query complexa sem índices evidentes
Gravidade: Média
Arquivo: app/ocorrencias/index.php

Problema: JOIN de 4 tabelas com GROUP BY sem certeza de índices em ocorrencias.id_reserva, ocorrencias.id_item_vistoria.

Impacto: Degradação severa de performance com crescimento dos dados.

Correção:


CREATE INDEX idx_ocorrencias_reserva ON ocorrencias(id_reserva);
CREATE INDEX idx_ocorrencias_item ON ocorrencias(id_item_vistoria);
18. Charset utf8 em vez de utf8mb4
Gravidade: Média
Arquivo: config/db.php (ou equivalente)

Problema:


$conn->set_charset('utf8');
utf8 no MySQL suporta apenas 3 bytes — emojis e alguns caracteres especiais causam erro silencioso ou truncamento.

Correção: $conn->set_charset('utf8mb4');

19. Erros em endpoints AJAX retornam HTML em vez de JSON
Gravidade: Média
Arquivo: config/init.php

Problema: die("Falha na conexão: ...") retorna HTML quando a rota é AJAX.

Impacto: Frontend quebra tentando parsear JSON e recebe HTML.

20. Ausência de X-Frame-Options e X-Content-Type-Options
Gravidade: Média
Arquivo: config/init.php

Problema: Nenhum desses headers de segurança está presente.

Impacto: Vulnerabilidade a clickjacking e MIME sniffing.

Correção:


header("X-Frame-Options: DENY");
header("X-Content-Type-Options: nosniff");
21. Código duplicado em todas as páginas de criação
Gravidade: Média
Arquivos: Todos os create.php do projeto

Problema: O padrão csrf_verify → GET_LOCK → validar → inserir → RELEASE_LOCK está copiado em pelo menos 6 arquivos. Um bug corrigido em um não é corrigido nos outros.

Impacto: Bugs se propagam assimetricamente. Manutenção multiplicada.

22. Log de auditoria não registra o que mudou
Gravidade: Média
Arquivo: includes/helpers/log.php

Problema: registrar_log() registra que algo foi editado, mas não registra os valores antes/depois.

Impacto: Auditoria ineficaz — impossível saber o que foi alterado.
